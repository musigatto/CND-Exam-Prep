# Typical Log Format and Logging Approaches (§15.LO#01c)

> **LO#01: Understand logging concepts** _(Mod 15 p4)_
> Covers pp10–13.

## Typical Log Format _(Mod 15 p10)_

A log file contains various types of valuable and **actionable** information — but only **proper log analysis and monitoring** turns it into actionable information.

### Types of information included in a log

| # | Printed field | What the p10 prose says about it |
|---|---|---|
| 1 | **User identification information** | "authenticated user information should also be available in a log" |
| 2 | **Date and time** | "The **timestamp** is an important item in any log as it tells when an event occurred" |
| 3 | **Type of event** | — |
| 4 | **Success or failure indication** | — |
| 5 | **Event origination point** | — |
| 6 | **Description** | "a description of the event and **why** it occurred is also recorded" |
| 7 | **Severity** | — |
| 8 | **Service name** | — |
| 9 | **Protocol** | — |
| 10 | **User** _(printed on p11)_ | — |

Also stated in the p10 prose but **not** part of the printed list:

- **IP address information** — "In a network-based event, the IP address information is also present in a log"
- **Authenticated user information**

### Why the timestamp dominates

- **All systems must be configured to synchronize their time from an authoritative time source**
- The timestamp helps in **filtering data in search results** and in identifying the logs that are **not matching the standards** and require attention
- It helps **correlate events from multiple systems** and present the complete picture of an event

### What must never reach a log file _(Mod 15 p11)_

Never transmitted to log files: **private or protected information**, plus —

- passwords · encryption keys · bank information · credit card information
- personal identifiable information · personal health information · source code · etc.

**Only the following should be sent to a log file** _(Mod 15 p11)_:

1. Initialization/clearing of audit logs
2. Creation/deletion of system-level objects
3. All access to the log
4. All administrative access
5. All actions taken by administrators
6. All actions taken by a person having **root or administrative privileges**

## Logging Approaches _(Mod 15 pp12–13)_

Logs are stored **either on local disks or the central server, depending on the size of the system**.

### Local Logging _(Mod 15 p12)_

- **Definition** — logging user activities in the host machine; "the process of writing logs into files stored on the local disk"
- **Used by** systems that have a **limited number of hosts**
- **Scaling limit** — with many hosts it becomes difficult to manage and analyze logs, and complicated to identify security-related events across multiple log files on multiple servers. **Common solution → centralized logging**

Instances when a host machine generates a log record _(Mod 15 p12)_:

1. System crash, shutdown, restart, or startup
2. Failed/successful modification of user credentials and access rights such as **account updates, creation, and deletion**
3. Successful/failed alteration of **user access privileges**
4. Exceeding the thresholds or crossing dangerous levels of parameters such as **disk space, memory, or processor load**
5. Successful/failed modification of the **system configuration** and **software updates**
6. **Installation and uninstallation of software**

### Centralized Logging _(Mod 15 pp12–13)_

- **Definition** — storing the logs generated by the **network devices** on a central server; "the process of **collecting and aggregating** logs in one central location"
- **It works in four parts:** **log collection, transport, storage, and analysis** _(Mod 15 p13)_ → [[15-LO08c-Log-Collection-and-Log-Transmission]]

Benefits _(Mod 15 p13)_:

1. Logs in a central location are **indispensable when troubleshooting security-related problems and determining why they happened**
2. Enables **proactive management** of the network
3. Facilitates **in-depth data analysis** and delivers greater value
4. **Minimizes the risk of losing data**
5. **Enhances network security**

Instances when a network device generates a log record in a central server _(Mod 15 pp12–13)_:

1. Addition/deletion of network devices
2. Changes implemented in _(p12)_ / to _(p13)_ network settings
3. Changes to _(p12)_ / in _(p13)_ user access to the network
4. Successful/failed user access to the network **initiated to/from the computer**
5. Network crashes
6. Applications installed/uninstalled in the network
7. Changes to the **firewall policy**
8. Additions, deletions, and changes of **administrative accounts**
