# Linux Log Format and Severity Levels (§15.LO#03b)

> **LO#03: Discuss log monitoring and analysis on Linux systems** _(Mod 15 p36)_
> Covers pp41–43.

## Linux Log Format _(Mod 15 p41)_

"The **system log file** provides information about **where messages are logged**."

**Figure 15.11 — Linux log format** _(Mod 15 p41)_

| Part of the format | Value printed in the figure |
|---|---|
| **Type of Log** | `crit` |
| **Severity of Log** | Any type of severity log |
| **Log File Location** | `/var/log/maillog` |

> "All severity logs pertaining to mail are written to /var/log/maillog"

So a `syslog.conf` directive names the **log type** and the **severity**, and the **file** the matching messages are written to.

### Anatomy of a log line _(Mod 15 p42)_

"Each line of the log file is divided into **two portions**: **message selector** and **action field**."

| Portion | Meaning | Printed values |
|---|---|---|
| **Message selector** | "represents the type of message to log. It is a **combination of log type and level**" | `*.info.none;news.none;authpriv.none;cron.none` · `kern. *` · `authpriv. *` · `mail. *` |
| **Action field** | "describes the **type of action** to be applied to the message. It indicates a **log file location**" | `/dev/console` · `/var/log/messages` · `/var/log/secure` · `/var/log/maillog` |

`kern. *` — **`*` indicates "all"**, i.e. all messages generated by the kernel.

### Worked examples _(Mod 15 p42)_

| # | Printed description | Selector | Action |
|---|---|---|---|
| 1 | "Log all **kernel** messages to the **console**" | `kern. *` | `/dev/console` |
| 2 | "Log anything **(except mail)** of level **info or higher**. Do not log private authentication messages" | `*.info.none;news.none;authpriv.none;cron.none` | `/var/log/messages` |
| 3 | "The **authpriv** file has **restricted access**" | `authpriv. *` | — |
| 4 | "Log all the **mail** messages in **one place**" | `mail. *` | `/var/log/secure` + `/var/log/maillog` |

## Severity Level and Value of Linux Logs _(Mod 15 p43)_

> "The **combination of Linux log file(s) and severity levels** facilitates determination of **what is logged and where that information is stored**."

- "When a system logger receives messages from multiple programs, it will make decisions as to **what to keep and what to discard** on the basis of severity levels defined by the **selector**"
- "There are **eight severity levels** for sending a message in Linux, **starting from level 0 to level 7**"
- "The **highest severe message is at level 0**, and the **lowest severe message is at level 7**"

### Printed table

| Severity Level | Severity Value | syslog.conf Extension | Meaning |
|---|---|---|---|
| **Emergency** | *(not printed)* | `.emer` | System is unusable |
| **Alert** | 1 | `-alert` | Action must be taken immediately |
| **Critical** | 2 | `.crit` | Critical conditions |
| **Error** | 3 | `.err` | Error conditions |
| **Waming** *(as printed)* | 4 | `.warning` | Warning conditions |
| **Notice** | 5 | `.notice` | Normal but significant condition |
| **Info** | 6 | `.info` | Informational messages |
| **Debug** *(label not captured in the table; named in the prose)_ | 7 | `.debug` | Debug-level messages |

### The same eight levels in the p43 prose

| Level | Name | Printed definition |
|---|---|---|
| **Level 0** | Emergency | emergency conditions where the **system comes unusable**; e.g. imminent system crash |
| **Level 1** | Alert | conditions that require **immediate actions**; e.g. a corrupted system database |
| **Level 2** | Critical | critical conditions such as a **hardware error** |
| **Level 3** | Error | error messages |
| **Level 4** | Warning | warning messages |
| **Level 5** | Notice | messages that are **not an error but require special attention** |
| **Level 6** | Information | informational messages |
| **Level 7** | Debug | messages that are **required during debugging** programs |
